# Посадка и адаптивность зданий

## Размеры и крыша

Высота берётся из исходного `height`, затем из положительного `num_floors` или `building:levels` × 3 м. Без этих данных используется условная высота по исходному типу здания: для `neutral` — **8 м**. Гаражи, сараи и явно измеренные низкие здания сохраняют свои значения. Оценка остаётся оценкой, а не измерением.

Векторный корпус и Three.js используют согласованную высоту карниза. Высота кровли вычитается из стен только для поддерживаемой скатной формы. Неизвестная или плоская форма не оставляет отсутствующую полосу стены под непрозрачной крышкой MapLibre.

## Привязка к рельефу

При включённом рельефе детали опираются на тот же средний центр вершин, что и MapLibre 6.7.0: учитываются все кольца без повторной замыкающей вершины. Для исходных тайлов повторяются внутренняя сетка EXTENT=8192 и округление центроида. Каждый фрагмент имеет собственную опорную точку. Это не площадной центроид и не первый угол корпуса.

У наземных стен есть такое же скрытое продолжение на 10 м вниз, как у векторного слоя. Оно закрывает нижнюю часть склона, не растягивая рисунок надземных этажей; поднятые части с `min_height > 0` не получают этот цоколь. Отрицательные абсолютные отметки допустимы, NaN/Infinity не попадают в вершины.

Переключение рельефа и обновление DEM вызывают пересборку, включая случай нулевой высоты. Предзагрузка, worker и синхронная сборка используют один расчёт опорной высоты и ключ кэша. Режим рельефа входит в ключ отдельно от численной отметки.

## Адаптивность

ResizeObserver обновляет бюджет деталей после изменения ширины окна: максимум 700 зданий и 90 000 вершин в мобильном режиме, 2000 зданий и 280 000 вершин на desktop. Устройства с coarse pointer сохраняют мобильный бюджет. Обратный переход на desktop восстанавливает его бюджет и normal map.

Размер фрагмента, масштаб камеры и экран не меняют физические высоту и основание здания. Площадь фрагмента, проекция и бюджет могут менять декоративные детали; UV привязаны к метрам и этажам, а не к размеру экрана.

## Проверки

```sh
npm ci
npm test
npm run typecheck
npm run build
```

6 сентября 2026 года проверенный код прошёл 388 тестов, TypeScript и production-сборку в GitHub Actions на Node из `.nvmrc`. Новые регрессии сначала проверены на исходном коде: до исправления они выявляли ошибки. Проверочный запуск: https://github.com/oostax/drgs-3d-region/actions/runs/34038393335.

`tests/building-grounding.test.ts` проверяет fallback, вторичный тег этажности, цельность стены под крышей, замкнутые кольца/дворы, округление тайла, некорректные отметки, длинный корпус на склоне, цоколь, worker-передачу, переключение DEM и desktop → mobile → desktop. Существующие тесты дополнительно проверяют позднюю загрузку DEM, LOD и ограничение вершин.

Для визуальной проверки на локальных данных: открыть длинный корпус без высоты, включить/выключить рельеф, менять масштаб 14–20 и наклон, уменьшить окно до 390 px и вернуть до 1440 px. Запуск: `npm run dev`, адрес `http://127.0.0.1:3200`.

## Ограничения

Это согласование двух рендереров, а не восстановление реальных высот или геодезии. При недоступном DEM используется нулевая отметка до загрузки. Очень крутой или ошибочный DEM, где поверхность выше рассчитанного карниза, всё ещё может перекрывать здание: MapLibre задаёт горизонтальную крышу по центру каждого фрагмента. Универсальное устранение такого случая требует общей коррекции векторного и детального слоя или исходных данных, а не подъёма одной крыши. Цоколь также ограничен глубиной 10 м. Визуальная проверка всех объектов и проверка на физическом смартфоне не заменяются unit-тестами.
