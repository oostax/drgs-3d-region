# География обращений Казани

На 4 сентября 2026 года **192 обращения однозначно сопоставлены с 74 реальными улицами**. Это уличная точность: весь связанный участок/улица из OSM, а не установленные дома или места каждого происшествия. Пользовательские тексты и адреса не передавались внешним сервисам.

## Что есть в исходной книге

Проверен последний завершённый источник `incidents` в локальной SQLite, только чтение. По Казани — **941 обращение**, **23 группы тем**, даты создания от 1 до 31 июля 2026 года. Отдельные колонки `street` и `object` присутствуют:

| Поле | Заполненных строк | Различных непустых значений |
| --- | ---: | ---: |
| Улица | 393 | 152 |
| Объект | 52 | 26 |
| Населённый пункт | 513 | 2 |

Текст есть у всех 941 записей, но автоматический конвейер ниже его не использует и не возвращает целиком в API списка. Простая локальная диагностика обнаружила у 213 текстов признаки упоминания улицы, у 63 — дома/корпуса. Это только кандидаты для следующего этапа, не доказанные адреса. У 30 из 52 значений «объект» есть цифры; отдельного номера дома нет, и цифра в названии объекта не приравнивается к дому. Никакие полные тексты, ФИО или телефоны в этот документ не включены.

Ранее метка «24 сигнала Казани» открывала 1 публичную новость и 23 темы. Она не обозначала 24 разных места или 24 обращения.

## Публичный индекс и точность

Локальный кэш OpenFreeMap содержал 185 подходящих тайлов с `transportation_name` на zoom 12–14 и 1 085 названий в охвате Казани. Они показали наличие материала для сопоставления, но тайловая геометрия обрезана и зависит от просмотренного охвата. Для рабочего результата загружены **полные именованные дорожные ways по всей публичной границе Казани** — [OSM relation 367666](https://www.openstreetmap.org/relation/367666).

Скрипт [build_street_index.ts](../scripts/build_street_index.ts) делает один общий запрос города к Overpass без имён улиц из обращений, клиентских данных или текстов. Он не открывает SQLite и приватные файлы. Получено **7 464 ways**, **2 187 нормализованных имён**, **3 006 связных компонентов**; индекс — около 2,6 МБ. Время получения — `2026-09-04T12:30:24.134Z`. Публичные артефакты находятся в `data/public/kazan-streets-osm.json` и `data/public/kazan-street-index.json`.

Каждый компонент сохраняет полную `LineString`/`MultiLineString`, навигационную точку на геометрии, bbox, ссылки на исходные OSM ways и дату снимка/получения. Отдельные компоненты с одним именем не склеиваются произвольной прямой. Топология использует исходные OSM node ID. Раздельные проезжие части или фрагменты одного имени могут поэтому остаться неоднозначными; это сознательно консервативное ограничение текущего алгоритма.

Сопоставление выполняется только внутри Казани, по точному нормализованному имени и типу улицы, если он указан. Поддержаны регистр, `ё/е`, точки, обычные сокращения и порядковые номера. Нечёткий поиск, ближайшая улица, транслитерация и догадки по ГОСБ/ИНН не используются. Уникальное имя из OSM даёт `precision=street`, `confidence=medium`; это уверенность в сопоставлении названия, не точность места обращения.

## Подтверждённое покрытие и API

| Результат | Обращений |
| --- | ---: |
| Однозначная улица | 192 |
| Несколько кандидатов | 187 |
| Без совпадения | 562 |
| Всего | 941 |

Из 562 несовпадений у 548 нет `street`, у 14 непустое значение пока не найдено. Остаток без однозначной привязки — **749**, он сохраняется доступным.

`/api/incidents?mode=work&territory=mo-92701000` сохраняет пагинацию 50 записей и итог 941, добавляет `items[].geolocation` и `geocoding={streetMatched:192,ambiguous:187,unmatched:562}`. Геолокация содержит статус, точность, геометрию, источник, метод, дату, число кандидатов и пояснение. Старое поле `unlocated` по-прежнему относится к невозможности установить муниципалитет; для уличного покрытия используется новый объект `geocoding`.

Исходные XLSX и SQLite в этом конвейере не переписываются: геопривязка вычисляется при чтении текущего завершённого среза по версии публичного индекса. Исходное `data_json.geocoding_status=not_geocoded` остаётся метаданными импорта, а результат текущего сопоставления находится в новом `geolocation`.

`/api/atlas?mode=work&territory=mo-92701000` теперь содержит **125 внутренних карточек**: 102 группы «тема + найденная улица» с 192 обращениями и 23 остаточные территориальные темы с 749. В одной и той же теме найденные записи вычитаются из остатка. В региональном ответе — 540 внутренних групп, сумма записей остаётся **6 374**. Тематические итоги также сохраняются. Публичные новости добавляются отдельно и не входят в сумму обращений.

У найденного сигнала: `precision=street`, `siteGeometry` — полная дорожная геометрия, `siteBbox`, `coordinateSourceUrl`, `locationVerificationMethod`, `relatedSources`, `geographyNote`. Координата предназначена для навигации к улице, а не для обозначения точного адреса. `lifecycle.status=unknown`, `currentStatusVerified=false`, `animationEligible=false`: обращения июля не доказывают нынешнюю стройку, аварию или пожар. Сцена может использовать настоящую геометрию улицы только с явным историческим/иллюстративным смыслом, без платформы и случайного дома.

Рабочие ответы проверены через фактический HTTP на 127.0.0.1:3200: итоговые суммы 941/6 374 не изменились, типы геометрии корректны. В публичном atlas внутренних групп — 0, `/api/incidents?mode=public` возвращает пустые записи. Список никогда не добавляет полный текст обращения.

## Воспроизведение и проверки

```sh
./node_modules/.bin/tsx scripts/build_street_index.ts
./node_modules/.bin/tsx --test tests/incident-geography.test.ts tests/core.test.ts
./node_modules/.bin/tsx --test scripts/test_backend.ts
npm run typecheck
```

Без `--refresh` скрипт повторно строит индекс из уже сохранённого публичного OSM extract. `--refresh` повторяет публичный городской запрос; он не выгружает адреса обращений. Обновление индекса подхватывается сервером по mtime, при его отсутствии все записи остаются доступными на уровне территории.

Подтверждено: **6 новых географических + 10 core тестов**, **7 backend тестов**, **typecheck**. Проверены нормализация, различие типов улиц, неоднозначные компоненты, отсутствие ближайшей подстановки, полная геометрия/источники, сохранение сумм, режимы и отсутствие индекса. Build и новый сервер в этой подзадаче не запускались. Браузерная приёмка новых уличных маркеров/сцен и финальный production-пакет ожидаются.
