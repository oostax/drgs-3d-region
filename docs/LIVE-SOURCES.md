# Источники живой карты Татарстана

## Реестр и покрытие

`data/live/sources.json` — проверяемый реестр кандидатов, а не заявление о том, что все адреса доступны и разрешены к обработке. Раздельные `fetch_allowed`, `ai_allowed` и `display_allowed` не выводятся друг из друга. Статус `active` получают только источники с читаемым адаптером и проверенной политикой использования. Техническая проверка кандидата сама по себе его не активирует.

Начальный реестр содержит 112 записей: официальные и оперативные ленты, официальный каталог сайтов муниципалитетов и территориальный каталог Татмедиа. У сайтов Татмедиа обнаружены районные RSS, но опубликованное редакциями условие требует письменного согласия на воспроизведение и распространение. Поэтому эти строки сохранены для discovery со статусом `rights-review`, а загрузка, AI-анализ и показ выключены.

`data/live/source-coverage.csv` и `coverage.json` содержат **956 строк данных**: 43 района, 2 городских округа и 911 муниципальных поселений. Регион `RU-TA` записан в метаданных реестра и не считается муниципальной строкой покрытия. Прямая районная запись наследуется поселениями только как потенциальный канал: она не доказывает наличие свежей новости о каждом селе.

`data/live/localities.csv` содержит 911 официальных муниципальных поселений и их административные центры из существующего ОКТМО-справочника проекта. Это не полный перечень всех деревень и адресов. Координата — ранее проверенная точка подписи муниципальной территории; она не становится координатой события.

Пересборка детерминированных файлов:

```bash
python3 scripts/live/registry.py
```

## Worker и база

Runtime хранится в `data/live/atlas-live.sqlite` с WAL. Он не содержит клиентские, банковские, кадровые или сделочные данные. При первом запуске worker переносит существующие публичные `signals.json`, сохраняя `Signal.id` как `legacy_id`, alias, редакционно проверенную геометрию и lifecycle. Backfill, legacy, повторная публикация и правка никогда не получают `notify_eligible=1`.

```bash
python3 scripts/live/worker.py --once
python3 scripts/live/worker.py --run
python3 scripts/live/worker.py --enqueue
python3 scripts/live/worker.py --backfill 60
python3 scripts/live/worker.py --check-sources
python3 scripts/live/worker.py --check-sources --include-candidates
python3 scripts/live/worker.py --export
```

`--enqueue` не захватывает singleton lock и складывает ровно один `manual-refresh` job, пока предыдущий находится в `queued` или `running`. Daemon проверяет очередь не реже раза в пять секунд. Если daemon не работает, локальный API может после enqueue запустить `--once`; этот процесс заберёт тот же job. Исторические задания имеют меньший приоритет, обрабатываются по одному источнику после новых материалов и ограничены 60 днями. Первый снимок ранее не виденной ленты считается baseline и не создаёт уведомлений.

Планировщик допускает четыре HTTP-запроса одновременно и один запрос на host. Он использует ETag/Last-Modified, ограничение размера, timeout, jitter и экспоненциальную задержку ошибок. Для серверов, цепочка которых отсутствует в Python/certifi, применяется системный `/usr/bin/curl` с включённой TLS-проверкой; небезопасный режим не используется. Отсутствие материала или удалённое Telegram-сообщение не закрывает событие.

## Анализ и география

Без AnyModel worker выполняет минимальную детерминированную классификацию и ставит документу `rule_based_queued`, если для источника разрешён AI-анализ. OpenAI-совместимый адаптер принимает только публичный текст источников с `ai_allowed=1`, ограничивает один одновременный запрос и валидирует JSON, перечисления и точное совпадение evidence spans. Ответ модели с координатами отклоняется целиком.

Адреса модели остаются кандидатами. Точная метка здания возможна только после отдельного сопоставления адреса с контуром и фиксации источника географии. Автоматический текстовый анализ не включает физическую сцену. Сцена ремонта или техники требует точной геометрии и явного актуального подтверждения работ.

Переменные окружения:

| Переменная | Назначение |
|---|---|
| `ATLAS_LIVE_DB` | Путь runtime SQLite |
| `ATLAS_ANYMODEL_URL` | Базовый OpenAI-совместимый URL, обычно с `/v1` |
| `ATLAS_ANYMODEL_API_KEY` | Локальный ключ AnyModel |
| `ATLAS_ANYMODEL_MODEL` | Идентификатор модели |
| `ATLAS_ANYMODEL_MAX_TOKENS` | Лимит ответа, по умолчанию 1200 |
| `ATLAS_LIVE_PYTHON` | Явный Python для LaunchAgent |
| `ATLAS_TELEGRAM_API_ID` | Telegram MTProto API ID |
| `ATLAS_TELEGRAM_API_HASH` | Telegram MTProto API hash |
| `ATLAS_TELEGRAM_SESSION` | Локальный путь или имя session |

## Telegram

Telegram-коннектор опционален и по умолчанию выключен. Он использует только Telethon 1.44.0, локальные MTProto credentials и allowlist источников с `consent_status=explicit`, `ai_use=true`, `enabled=true`. Bot token не заменяет `api_id` и `api_hash`. Команды адаптера разделяют `backfill`, `listen` и `reconcile`; ключ документа — `(source_id, message_id)`, edits создают версии, delete создаёт tombstone. Tombstone применяется только к уже сохранённому документу, использует его исходную дату, добавляет evidence `dispute`, выключает уведомление и не закрывает событие. Неизвестное старое удаление без исходного текста игнорируется. Уведомления об удалении Telegram не считаются гарантированными, поэтому reconcile обязателен.

Worker никогда не ищет каналы, не читает личные диалоги и не отправляет сообщения. Для включения конкретного канала сначала документируются согласие, права на AI-анализ и показ.

## Автозапуск и проверка

```bash
sh scripts/live/install_launch_agent.sh
python3 tests/test_live_pipeline.py
```

Installer выбирает `ATLAS_LIVE_PYTHON`, затем проектный `.venv/bin/python`, затем системный `python3`. Он только записывает и проверяет plist, но не активирует LaunchAgent. Worker сам читает корневой `.env.local`: принимает только буквальные пары `ATLAS_*=value`, не вычисляет shell-подстановки и не перезаписывает уже экспортированные переменные. Пока Mac выключен, спит или не имеет сети, сбор не является непрерывным; UI показывает heartbeat и фактическое отставание.

Перед подключением нового источника проверяются дата публикации в самом источнике, валидность карточек, устойчивый внешний ID, права на загрузку/AnyModel/показ, география и поведение при ошибке. Успешный HTTP 200 без датированных материалов не считается успехом.
