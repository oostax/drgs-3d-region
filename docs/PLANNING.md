# Адреса, возможности и встречи

Панель работает только с локальным портфелем в рабочем режиме. В презентационном режиме API планирования возвращает `null`, список планов пуст, запись адресов и планов запрещена. Исходные XLSX и список клиентов не отправляются в сервисы геокодирования.

## Сопоставление адресов

Открытый индекс `public/data/organization-addresses.json` содержит источник адреса, ИНН, координаты, точность и дату проверки. Автоматически сопоставляется только точный ИНН. Совпадение названия и противоречивые публичные адреса остаются кандидатами. Признак `autoMatchEligible: false` запрещает автоматическое принятие адреса.

В локальной таблице `organization_locations` юридический адрес, офис и место встречи хранятся отдельно. Ручная правка требует подтверждения организации, адреса и точности координат. Повторное сопоставление открытого индекса сохраняет ручные подтверждения. Адрес с координатами населённого пункта или территории не используется как точное место встречи.

Проверка на поставке 4 сентября 2026 года: 6 публичных записей, из них 5 сопоставлены по ИНН и одна оставлена конфликтным кандидатом. У четырёх записей есть координаты зданий. Это частичное адресное покрытие портфеля из 11 408 организаций. Место встречи не подтверждено ни одной публичной записью; для закрытых на ремонт учреждений особенно необходимо уточнить фактический приём.

## Объяснимые возможности

Правила показывают факты, гипотезу, продукт для обсуждения и следующий шаг. Используются текущие предложения, рост месячного ФОТ между мартом и июлем и нулевые счётчики встреч. Пустые значения не считаются нулями; конфликтные встречи не дают правило отсутствия встреч. Исторические предложения не подменяют текущие.

Если самая новая загрузка ФОТ или встреч не завершена либо завершилась ошибкой, соответствующие правила временно не формируются: эти таблицы обновляются порциями и не должны становиться основанием для новых выводов в промежуточном состоянии.

Рост ФОТ не доказывает расширение штата: причиной могут быть премии, сезонность или иные выплаты. Продукты предлагаются для обсуждения, без утверждения об одобрении, доступности, лимите или полномочиях организации. Справочные возможности зарплатного проекта приведены в [документации Сбера](https://developers.sber.ru/docs/ru/sber-api/scenarios/salary/salary-project/overview).

КМ предлагается автоматически только при точном совпадении имени в текущем предложении с актуальной локальной версией штата. Если закрепление неоднозначно, ответственный остаётся не выбран. Доступность сотрудника по календарю не проверяется.

## Порядок и время

План хранится в `meeting_plans` и содержит до 12 организаций. Время задаётся по Москве, UTC+3. Дефолт — следующий будний день в 09:00; календарь государственных праздников не подключён. Пользователь задаёт длительность встречи и буфер. Встречи за пределами ориентировочного окна 09:00–18:00 по будням отмечаются отдельно.

Порядок можно сохранить вручную или построить жадным выбором ближайшей следующей точки. Это полезная эвристика, а не доказанно оптимальный маршрут. Без начальной точки дорога к первой организации не учитывается; возвращение после последней встречи не добавляется автоматически.

Первичный маршрут — явно обозначенная оценка: геодезическое расстояние по прямой умножается на коэффициент объезда, время рассчитывается по заданной скорости. Такая линия не изображает реальную дорогу.

Кнопка «Уточнить по дорогам · OSRM» доступна после отдельного согласия передать координаты выбранных точек. Сервер отправляет только числовые координаты на фиксированный `router.project-osrm.org`, без названий, ИНН, финансов, cookie и авторизации. Ограничение — 8 встреч, таймаут 12 секунд; переходы на другой URL запрещены. Порядок остановок сохраняется.

Ответ OSRM даёт дорожную геометрию и длительность участков; план пересчитывает время встреч с буферами. Сохраняются метод, источник и время расчёта. Пробки, текущие перекрытия и доступность участников не подтверждаются. При недоступности сервиса предыдущий маршрут сохраняется с явным сообщением. Семантика координат и результата основана на [официальной документации OSRM](https://project-osrm.org/docs/v5.24.0/api/#route-service).

## Проверено

`tests/planning.test.ts` проверяет изоляцию публичного режима, точный ИНН против кандидатов, сохранение ручного места встречи, отсутствующие имена организаций, `NULL`/ноль в правилах, порядок и московское время с буферами, закрепление КМ, согласие на отправку координат и fallback дорожного сервиса. Все данные тестов синтетические, база и индекс временные.

HTTP API на порту 3200 проверен с реальным локальным портфелем: 40 записей на странице, 6 сопоставленных адресов/кандидатов, 6 вариантов КМ; публичный ответ — `null`. Отдельная проверка доступности OSRM использовала только две публичные координаты из его документации: `Ok`, `LineString` из 133 точек, один участок. Частные координаты для этой проверки не передавались. Сохранение подтверждённых встреч на реальных клиентах не выполнялось автоматически.
