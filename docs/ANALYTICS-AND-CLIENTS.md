# Аналитика и клиентский портфель

## Навигация

«Аналитика» в нижней навигации и название текущей территории открывают одну
сводку. Поиск остаётся у «Найти на карте». Выбор дочерней/родительской территории
в сводке не перемещает карту. Кнопка «Показать на карте» перемещает явно;
закрытие сохраняет камеру. Раздел «Карта → Организации и возможности» связан
с этой сводкой и существующими карточками/планированием встреч.

Линейка масштаба и оба переключателя симуляции удалены. Городская симуляция
включена в 3D автоматически; 2D, скрытая вкладка, reduced-motion и бюджеты
устройств сохраняют свои защитные ограничения.

## Данные территории

- Обращения берутся из последнего завершённого локального источника `incidents`.
  Историческая выгрузка не выдаётся за текущие происшествия. Показываются период
  записей, дата импорта, темы и поступление по месяцам. Месячные столбцы не
  являются динамикой незакрытого остатка и не доказывают полноту месяца.
- Индекс: `100 × незакрытые / (незакрытые + закрытые)`. «В работе» — подмножество
  незакрытых. Неизвестные статусы отдельно, без включения в знаменатель;
  неизвестная дата не превращается в выдуманную. При пустом знаменателе — «—».
  Это доля в источнике, не индекс благополучия и не жалобы на 1000 жителей.
- Муниципальная и поселковая иерархия использует имеющийся справочник. Данные,
  известные только на уровне родителя, остаются на нём. Районы города не
  выдумываются, если их границ/сопоставления нет в подключённом справочнике.
- Публичная повестка отдельно: полная лента с прохождением страниц, 30/45/60/180
  календарных дней. При изменении версии во время чтения расчёт повторяется;
  неполная выборка не объявляется полной. Старые, будущие и недатированные
  публикации не попадают в выбранный период.
- Банковская сеть использует существующий `territoryPriorities`: повторы одного
  банка/места объединены, важны доказанные координаты и дата проверки до 365 дней.
  Сбер / доступные точки — не клиентская доля рынка и не доказательство работы
  отделения. Баллы приоритета объясняются рядом с исходными фактами.

## Портфель Сбера

Рабочий режим подключает организации, предложения выбранного завершённого
среза, зарплатные показатели, квартальные счётчики встреч и локальные будущие
планы. Данные из разных срезов не суммируются. Повтор одного ID предложения
с одинаковыми значениями учитывается один раз; конфликтующие/пустые ID
исключаются из сумм и показываются как проблема качества.

ОД — ожидаемый доход, не полученный доход; неизвестные суммы не равны нулю.
ФОТ сравнивается только на одной и той же группе с двумя известными значениями.
Изменение выплат не доказывает рост персонала. При незавершённой замене
изменяемой зарплатной/контактной таблицы её показатели становятся неизвестными,
а не смешиваются с прежней версией.

Клиентский ключ — существующий ИНН + ГОСБ. География — точный адрес внутри
реального полигона с учётом отверстий. ГОСБ, название клиента и центр
муниципалитета не используются как координаты. В территориальных суммах только
размещённые здесь организации; полный портфель и нераспределённый остаток
показаны отдельно. Юридический адрес не объявляется местом деятельности.

## Организации и возможности

По умолчанию видны все клиенты с предложениями выбранного среза, включая
неоднозначные ID, требующие проверки; можно открыть весь справочник.
Поиск по ИНН, названию, ГОСБ и КМ; фильтры географии, продукта, стадии,
подтверждённого адреса и повода. Список по 40 записей, карта — все точки
фильтрованного набора, а не только текущая страница. Совпадающие адреса и
кластеры раскрывают всех участников с подгрузкой списка. В клиентском разделе
банковские, событийные маркеры и достопримечательности временно скрыты:
DOM-маркер банка не может перехватить нажатие на клиента по тому же адресу.
Сохранённые настройки слоёв не меняются и возвращаются в других разделах.

Поводы — не автоматические продажи: длительная стадия из поля источника,
предложения без зафиксированных контактов, рост зарплатных выплат, публичное
событие с точным совпадением ИНН, отсутствие ОД, адреса и конфликт ID.
Каждый повод содержит факты и следующий шаг для проверки. Для исторического
среза не выдаются рекомендации будто предложения действуют сейчас.

## Как разместить клиентов

1. Сопоставить локальный открытый справочник по точному ИНН. Подтверждённые
   ручные точки при синхронизации сохраняются.
2. Выгрузить очередь «без адреса» в CSV, дополнить разрешёнными рабочими
   адресами и воспользоваться существующим импортом с предпросмотром,
   подтверждением и восстановлением предыдущего импорта. CSV защищён от
   формул в названиях клиентов.
3. В карточке «Указать адрес / встречу» подтвердить офис или место встречи.
   После закрытия карточки список и карта обновятся без перезапуска.
4. Необязательно: добавить `ATLAS_DADATA_TOKEN` только в локальный `.env` и
   перезапустить сервер. В разделе адресов требуется явное согласие на
   передачу ИНН. Даже без сумм запросы могут раскрывать состав клиентского
   списка; использовать только при разрешённой передаче.

DaData: https://dadata.ru/api/find-party/ — фиксированный серверный endpoint
`findById/party`, точный ИНН юрлица и `branch_type=MAIN`. Геоточка принимается
только при точности до дома (`qc_geo=0`, дом и валидные координаты). Иначе
адрес остаётся кандидатом. Данные ИП не используются для поиска жилого адреса:
нужен подтверждённый офис/место встречи. Условия зависят от аккаунта поставщика.
Ключ не передаётся браузеру; суммы, контакты и описание сделок не отправляются.
Пакет — до пяти организаций, таймаут и ограничение ответа; отмена прекращает
последующие запросы, уже сохранённые адреса остаются. Ручная правка, выполненная
во время запроса, приоритетна. Изменение местоположений не меняет сами сделки.

Нельзя обещать 100% точек только по ИНН: без проверенного адреса клиент остаётся
в полном списке с причиной и следующим действием, а не исчезает с учёта.

## Безопасность и проверка

Новые приватные API требуют явного `mode=work`, loopback-хоста и своего Origin;
публичный режим не открывает приватную БД. Ответы `private, no-store`.
Реальные базы, `.env`, ИНН клиентов и токены не добавляются в репозиторий/CI.

`npm test`, `npm run typecheck`, `npm run build`. Браузерная проверка:
`.github/workflows/analytics-browser.yml`, `scripts/verify-analytics.py`.
Она использует только отдельную синтетическую БД: 85 клиентов, 80 совпадающих
точек, жалобы и публичные проекты. Это не визуальная проверка всего локального
набора пользователя и не гарантия покрытия адресов провайдером.

Для обновления: остановить сервер через Ctrl+C, затем
`git switch master && git pull --ff-only origin master && npm ci && npm run dev`.
Адрес `http://127.0.0.1:3200`. Код откатывается через `git revert` коммита функции,
без принудительного сброса истории и без удаления локальных баз.
