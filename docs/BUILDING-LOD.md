# Дальняя застройка

Проверено локально 4 сентября 2026 года. Проверка данных и алгоритма покрытия выполнена; визуальная приёмка камеры и производительность браузера остаются отдельными условиями завершения.

## Причина обрыва

И исходный PMTiles, и source/layers начинались на z13. Установленный MapLibre 6.7.0 использует разные уровни тайлов при наклонной камере. В `covering_tiles.ts` рассчитанный дальний тайл ниже `source.minzoom` отбрасывается, а не автоматически заменяется ближайшим z13. Поэтому изменение только расстояния камеры или размера Three-моделей не решает отсутствие геоданных.

API [`setSourceTileLodParams`](https://maplibre.org/maplibre-gl-js/docs/API/classes/Map/#setsourcetilelodparams) управляет диапазоном LOD и относительным бюджетом тайлов. В установленной версии исходные значения — 9.314 уровня и коэффициент 3. Для зданий выбран отдельный диапазон 4 уровня / коэффициент 3; это ограничение геометрического покрытия, а не гарантия FPS.

## Выполненное изменение данных

Скрипт [extend_building_lod.py](../scripts/extend_building_lod.py) использует только ранее скачанные `building.geojsonseq` и `building_part.geojsonseq`. Сеть и внутренние данные не используются. Он собирает z10–12 через локальный Tippecanoe 2.82.0, добавляет их к исходному архиву и заменяет файл атомарно только после проверки.

На z10–12 применяется бюджет 512 KiB / 12 000 объектов на тайл с отбором самых маленьких полигонов при превышении. Геометрия упрощается и квантуется для масштаба. Искусственные квадраты вместо маленьких контуров отключены. Это дальнее представление доступной застройки; полнота мелких зданий на этих уровнях не заявляется. Все 50 577 исходных тайлов z13–15 сохранены побайтно, включая свойства и доступные контуры малых зданий. Это проверка неизменности архива, а не обследование всех реальных построек.

Архив вырос с 318 553 861 до 352 835 760 байт. Первый вариант без дальнего бюджета был отклонён после измерения тайла 4.77 МБ; он не является итоговым набором.

## Интеграция карты

Использовать [building-lod.ts](../src/lib/building-lod.ts):

```ts
// URL revision обходит старые браузерные Range-ответы и кэш заголовка PMTiles.
url: buildingTileSourceUrl(window.location.origin)
minzoom: BUILDING_MIN_ZOOM // 10
maxzoom: BUILDING_MAX_ZOOM // 15; далее используется overzoom
// После addSource, также после пересоздания стиля:
configureBuildingTileLod(map, 'atlas-buildings')
```

Основные слои `building` / `building_part` fill/extrusion также должны иметь minzoom 10, иначе source загрузится, но слои останутся невидимыми. Дорогие фасадные детали могут оставаться на близком масштабе. Конкретная окраска, тип здания и выбор материала принадлежат отдельному конвейеру и не изменены этим исправлением. Внутри одного source MapLibre выбирает соответствующий уровень; дополнительная непрозрачная подложка тех же зданий поверх деталей не требуется.

## Воспроизводимые проверки

```sh
data/public/.venv/bin/python scripts/test_building_lod.py
node_modules/.bin/tsx --test tests/building-lod.test.ts
data/public/.venv/bin/python scripts/extend_building_lod.py
```

Пять Python-тестов прошли: неизменность ближнего малого здания, несовместимые диапазоны, изменённый/потерянный detail tile, иерархия координат тайлов. Три TypeScript-теста на настоящем алгоритме установленного MapLibre прошли без браузера/WebGL: добавление дальних тайлов без замены ближних; исчезновение всего source при прежнем min13 на камере z13/pitch75 против непустого min10; overzoom z15 на улице и новый локальный ключ URL.

Повторный запуск без `--refresh` не меняет уже расширенный архив. При `--refresh` перестраиваются только дальние уровни. Основной `fetch_public_data.py --buildings` теперь запускает расширение после сборки детального архива, чтобы следующая загрузка не возвращала прежний minzoom13.

Не выполнены этой задачей: браузер, сервер, production-build, измерение GPU/памяти/FPS или физического смартфона. Первый общий typecheck был заблокирован параллельными изменениями оформления и маркеров; повторный прогон после их завершения прошёл.
