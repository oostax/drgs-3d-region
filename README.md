# Сбер Атлас

Локальный 3D-атлас для работы с государственным сектором. Татарстан — подробный пилот; Россия — обзорная карта для последующего расширения. Карта занимает основной экран, а карточки, источники и планирование открываются по действию пользователя.

Проект содержит муниципальные границы, доступные контуры зданий, восемь авторских архитектурных моделей, публичные сигналы, банковские объекты, локальный портфель, досье и планы встреч. Текущий этап — финальная браузерная проверка обновлённой карты и слоя симуляции. Подтверждённые проверки и ещё открытые условия готовности перечислены в [журнале проверок](docs/VERIFICATION.md).

## Запуск

Нужны Node.js 24.20.x (точная версия в `.nvmrc`), npm 11 и Python 3.11+. В текущей рабочей папке зависимости и данные подготовлены.

```sh
npm install
npm run dev
```

Открыть [локальный атлас](http://127.0.0.1:3200). Сервер слушает только локальный компьютер. Для запуска без режима разработки:

```sh
npm run build
npm start
```

Живой слой хранится отдельно в `data/live/atlas-live.sqlite`. Разовая проверка разрешённых источников и постоянный локальный сбор запускаются так:

```sh
npm run live:once
npm run live:run
```

`npm run live:backfill` ставит в низкоприоритетную очередь историю за 60 дней, `npm run live:export` создаёт JSON/CSV-выгрузку, а `npm run live:install` готовит LaunchAgent для macOS и печатает команду его явной активации. Параметры AnyModel и опционального Telegram MTProto перечислены в `.env.example`; bot token не заменяет `api_id`, `api_hash` и локальный вход. Telegram-зависимость устанавливается отдельно из `scripts/live/requirements-telegram.txt`, а каждый канал включается только после явного разрешения в реестре.

Перед `npm start` завершите сервер разработки: два сервера не должны занимать один порт. Запускайте команды из корня проекта, где находятся локальная SQLite и публичные данные. Конфигурация исключает приватные каталоги из трассировки сборки; фактическое отсутствие базы в новом standalone-пакете необходимо подтвердить после финальной сборки.

## Работа с картой

- На старте карта открыта, боковая панель свёрнута. Поиск находит территории, организации и объекты; карточка появляется после выбора.
- Масштаб меняется непрерывно колёсиком, жестами и кнопками `+`/`−`. Отдельного переключателя «Регион / Город / Объект» нет: состав видимых слоёв меняется по масштабу. Доступны 2D/3D, наклон камеры, компас и возврат к Татарстану.
- Часы «Время и жизнь города» используют местное время Казани, UTC+3. Можно вернуться к текущему времени или вручную провести день ползунком с шагом 15 минут. Освещение рассчитывается непрерывно с учётом даты: рассвет, день, закат и ночь не являются четырьмя фиксированными пресетами. Это модель солнечного положения, а не прогноз погоды.
- Цвета подложки, освещение архитектуры и декоративные окна реагируют на время. Рисунок фасадов — авторская визуализация, а не обследование окон каждого здания.
- Метка территории открывает связанные новости и группы тем; точность объекта указана отдельно. Факты, гипотеза и следующий шаг не смешиваются. География жилого комплекса или площадки не считается подтверждённым контуром конкретной школы.
- «Симуляция города» обозначает модельную анимацию, а не наблюдение реальных машин, людей или строительной техники. Слой можно приостановить. Новая логика движения и её стабильность ещё проходят отдельную проверку.
- В мобильной компоновке используются компактные элементы и раскрываемая панель. Есть режим без WebGL: `/?webgl=0`. Финальная проверка новой мобильной версии и измерения на физическом смартфоне пока не завершены.

## Организации и встречи

В рабочем режиме доступны поиск по названию или ИНН, ФОТ, счётчики встреч, текущие и квартальные предложения. Соседние срезы сравниваются по ID предложений одной организации; пропуски данных и предполагаемые даты отчётности показаны явно. Принадлежность к ГОСБ не определяет адрес клиента и не позволяет автоматически распределять портфель по муниципалитетам.

В панели планирования можно сопоставить открытые адресные источники, подтвердить адрес, выбрать организации и составить план дня. Юридический адрес, офис и место встречи хранятся отдельно. Из шести публичных записей пять сопоставлены с портфелем по ИНН, одна оставлена конфликтным кандидатом; четыре имеют координаты зданий. Это частичное покрытие 11 408 организаций, а не геокодирование всего портфеля. Места встреч требуют подтверждения, в том числе для учреждений на ремонте.

Объяснимые правила находят поводы для разговора по текущим предложениям, изменению месячного ФОТ и нулевым счётчикам встреч. Результат содержит факты, гипотезу, продукты для обсуждения и следующий шаг. Он не утверждает одобрение, лимит или применимость продукта.

План учитывает время Москвы, длительность встречи, буферы и выбранного КМ. Закрепление сотрудника определяется только при однозначной связи в источниках; его календарь и доступность клиента не проверяются. Порядок остановок можно задать вручную или приблизительно упорядочить по ближайшей точке.

Первичный маршрут — оценка по прямой, коэффициенту объезда и заданной скорости. Отдельная кнопка OSRM, после согласия пользователя, передаёт только координаты выбранных точек и получает дорожную геометрию. Названия, ИНН и суммы не отправляются. Пробки и актуальные перекрытия не учитываются; при сбое сервиса сохраняется предыдущая версия с указанием метода. До 12 встреч в плане, до 8 при уточнении через OSRM. Подробности — [адреса и планирование](docs/PLANNING.md).

«Досье встречи» сохраняет факты, источники, вопросы, действия и заметки локально. Страница печати позволяет использовать штатный диалог браузера для PDF. Презентационный маршрут по публичным объектам и рабочий маршрут встреч — разные сценарии. «Источники и импорт» показывает происхождение данных, фоновые импорты, версии штата, кластеры и банковские сводки.

## Данные и точность

Публичные артефакты находятся в `public/data`, загрузки и кэш — в `data/public`. Справочник Росстата от 1 сентября 2026 года содержит 956 муниципалитетов и регион: 957 записей сопоставлены с геометрией OSM. Это проверка покрытия и сопоставления, а не кадастровой точности границ.

PMTiles содержит 2 332 429 доступных контуров зданий Overture и 2 702 части зданий. У 597 зданий есть исходная высота, у 82 346 — этажность. Отображение: исходная высота → этажность × 3 м → условная высота по исходному типу здания. Для неизвестного типа (`neutral`) используется 8 м; гаражи, сараи и другие известные типы сохраняют отдельные низкие значения. Размер фрагмента тайла и масштаб камеры не меняют физическую высоту. Тайлы читаются частями с уровня 13. Полная инвентаризация всех реальных зданий и точные модели каждого фасада не заявляются.

Восемь авторских моделей: Кул-Шариф, Сююмбике, Спасская башня, Дворец земледельцев, центр семьи «Казан», Университет Иннополис, технопарк Попова и Белая мечеть. Координаты связаны с объектами OSM; пропорции и детали фасадов остаются художественным приближением. GLB high/low — в `public/models`, процедурные исходники — в `src/lib/landmark-models.ts`.

В банковском наборе 809 записей: 398 из реестра ЦБ и 411 дополнительных из OSM. У 466 есть координаты, включая 55 записей, сопоставленных с реестром ЦБ. Эти числа не равны количеству уникальных действующих офисов. Полнота всех отделений и банкоматов, услуги и часы работы не подтверждены.

Обзор России использует исторический набор 85 геометрий OSM. Актуальная полнота административной классификации всей страны не заявляется; детальные данные остальных регионов не подключены.

Новости сохраняют источник, дату публикации и статус проверки. Публикация о строительстве не подтверждает сегодняшний статус объекта. При недоступности источника остаётся предыдущий срез. Записи Excel с адресным текстом не превращаются автоматически в точные точки событий. Происхождение, лицензии и подробные ограничения — в [описании источников](docs/data-sources.md).

## Приватность и работа без внешней сети

`private-data/atlas.sqlite`, XLSX и загруженные книги исключены из публичных каталогов и Git. Внутренние API проверяют режим; запросы рабочего режима ограничены локальным Host/Origin. Публичные и рабочие досье разделены сервером. Презентационный API не возвращает внутренний портфель, адреса клиентов, штат или планы встреч.

Это однопользовательское локальное приложение, а не корпоративная система ролей. Корпоративная авторизация, CRM, совместная работа и календари не подключены. Внутренние строки Excel не передаются для массового геокодирования или внешнего ИИ. Единственная пользовательская операция маршрутизации передаёт выбранные координаты фиксированному дорожному сервису после явного согласия.

Подложка OpenFreeMap проходит через серверный кэш разрешённых картографических путей. Уже сохранённые тайлы доступны без внешней сети, пока работает локальный сервер. Весь мир заранее не скачивается; незагруженный тайл при недоступном источнике возвращает явную ошибку. Финальная проверка состава production-пакета остаётся обязательной.

## Проверки и разработка

Next.js, TypeScript, MapLibre, Three.js, PMTiles, better-sqlite3 и потоковый Python XML/XLSX. Повторный импорт и контрольные числа описаны в [IMPORT.md](docs/IMPORT.md).

```sh
npm run typecheck
npm test
./node_modules/.bin/tsx --test scripts/test_backend.ts
python3 -B scripts/test_import.py
```

Импортёр и его тесты используют стандартную библиотеку Python. У конвейера геоданных отдельные зависимости; этапы перечисляет `scripts/fetch_public_data.py --help`. Крупный PMTiles исключён из Git и восстанавливается соответствующим этапом конвейера.

Наличие команды или тестового файла не означает завершённую проверку последнего изменения. Фактические результаты и оставшиеся условия готовности — в [VERIFICATION.md](docs/VERIFICATION.md).
